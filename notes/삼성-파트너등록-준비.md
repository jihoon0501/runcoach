# 삼성 헬스 파트너 등록 준비

삼성은 공개 배포하는 앱의 **패키지명 + 서명 SHA-256**을 등록한 뒤에만 Data SDK 연결을 허용해요. 등록 전에는 개발자 모드가 켜진 기기에서만 동작해요.
요청서는 삼성 개발자 계정으로 로그인해야 열려서, **양식의 실제 항목은 확인하지 못했어요.** 아래는 일반적으로 필요한 정보를 미리 정리한 거예요. 양식에 다른 항목이 있으면 알려 주세요.

- 파트너십 요청 페이지: https://developer.samsung.com/SHealth/business-partner/m48wvqi1mt9w2w4c
- 절차 설명: https://developer.samsung.com/health/data/process.html
- 앱 검증(서명 등록) 설명: https://developer.samsung.com/health/data/guide/app-verification.html

## 1. 진행 순서 (이 순서가 중요해요)

SHA-256은 **스토어에서 실제로 배포되는 앱의 서명 키** 기준이라서, 패키지명과 서명 방식을 먼저 정해야 해요.

1. **패키지명 확정: `io.github.jihoon0501.runcoach`** (바꾸려면 `rename_package.py` 또는 Android Studio Refactor, 자세한 건 `패키지명변경.md`)
2. **업로드 키(키스토어) 만들기** → 아래 2번
3. **Google Play Console**에서 개발자 계정을 만들고, 확정한 패키지명으로 앱 만들기 → 서명된 AAB를 **내부 테스트**에 올리기
4. Play Console → 출시 → 설정 → **앱 무결성** → '앱 서명 키 인증서'의 **SHA-256** 복사
   - Play 앱 서명을 쓰면 사용자에게 배포되는 앱은 **구글이 보관한 앱 서명 키**로 서명돼요. 내가 만든 업로드 키의 지문과 달라요.
   - 삼성 문서도 배포에 쓰는 앱 서명 키를 앱 패키지명과 함께 삼성 시스템에 등록해야 한다고 안내하고, 지문은 Play Console의 앱 무결성에서 복사하라고 해요.
5. **삼성 파트너십 요청 제출**: 앱 패키지명과 서명(SHA-256)이 승인 후 삼성 헬스 시스템에 등록되고, 그렇지 않으면 개발자 모드가 켜진 때만 동작해요.
6. 승인 대기 중에는 내 폰(개발자 모드)에서 계속 테스트
7. 승인 후 **Play 내부 테스트로 설치한 앱**에서 연동이 되는지 확인
   - 앱 설정 → '앱 정보'의 **버전을 5번 누르면** 패키지명과 설치된 앱의 서명 SHA-256이 나와요. 삼성에 등록한 값과 같은지 비교하세요.

Play 없이 APK를 직접 나눠 줄 계획이라면 내가 만든 키스토어의 지문을 등록하면 돼요. 다만 일반 사용자에게 퍼뜨리기는 어려워서 공개 배포에는 Play를 권해요.

## 2. 서명 키(업로드 키) 만들기

**개인 키는 내 컴퓨터에서 직접 만들어야 해요.** 제가 대신 만들어 드릴 수 없고, 만들어서도 안 돼요. 파일과 비밀번호는 아무에게도 보내지 마세요(저한테도요).

**가장 쉬운 방법 (Android Studio)**
1. 메뉴 Build → **Generate Signed App Bundle / APK** → Android App Bundle → Next
2. Key store path 옆 **Create new...**
3. 키스토어 위치는 프로젝트 **밖**으로 (예: `C:\Users\<내 계정>\keys\runlog\release-keystore.jks`)
4. 비밀번호 설정(강력하게), Alias: `runlog-upload`, Validity: **25년 이상**(Play는 2033년 이후까지 유효한 키를 요구해요, 여유 있게 10000일 권장)
5. 인증서 정보(이름 등)를 입력하고 OK

**명령줄 방법** (`keytool`은 Android Studio에 들어 있는 JDK 안에 있어요)
```
keytool -genkeypair -v -keystore release-keystore.jks -alias runlog-upload -keyalg RSA -keysize 2048 -validity 10000
```
비밀번호는 명령에 직접 쓰지 말고, 물어볼 때 입력하세요.

**지문(SHA-256) 확인**
```
keytool -list -v -keystore release-keystore.jks -alias runlog-upload
```
출력의 `SHA256:` 줄이에요. 이건 **업로드 키** 지문이라서, Play 앱 서명을 쓰는 한 삼성에 등록할 값이 아니에요(1번의 4단계 값을 쓰세요). 다만 기록해 두면 Play Console에서 업로드 키를 확인할 때 쓸 수 있어요.

**보관**
- `.jks` 파일 + 비밀번호 + alias를 **비밀번호 관리자와 오프라인 사본 2곳**에 보관
- `keystore.properties`, `*.jks`를 git에 올리지 않기 (`.gitignore`)
- Play 앱 서명을 쓰면 업로드 키를 잃어도 Play 지원으로 재설정할 수 있지만, 번거로워요

## 3. 요청서에 쓸 내용 (붙여넣기용 초안, 영어)

**App name**: RunLog (final name to be confirmed)

**Signing certificate SHA-256**: [Play Console의 앱 서명 키 SHA-256]
**Distribution**: Google Play (Korea first)
**Privacy policy URL**: [공개 주소]
**Contact**: [이름 / 이메일]

**App description**
RunLog is a running coach for Samsung Galaxy Watch users. It reads the user's running and walking sessions and a few daily recovery signals from Samsung Health, builds a personalized weekly training plan, explains why the plan changed, and shows a daily readiness score. All processing happens on the user's device.

**Data access (read-only; no write access requested)**

| Data type | What we read | Why we need it |
|---|---|---|
| Exercise (running, walking) | Session summary and detailed logs (speed, heart rate, cadence) | Pace, split and segment analysis; weekly load; recovery-walk recognition |
| Sleep | Sleep duration and sleep score per night | Daily readiness score and training intensity advice |
| Heart rate | Overnight lowest heart rate | Resting heart rate proxy for the readiness score |
| Energy score | Daily energy score | Part of the readiness score |
| Skin temperature | Nightly average | Minor adjustment of the readiness score (change from the user's own baseline) |

We do not request blood oxygen or body composition. (The app's developer-only diagnostics screen, which is hidden in release builds, is the only code that references them.)

**Data handling**
Data is read after the user grants permission in Samsung Health, stored only in the app's private storage on the device, and deleted when the user taps "Delete all my data" or uninstalls the app. We do not operate a server and do not collect user data. Users may optionally enter their own Anthropic API key; in that case, only a summary of a run and recent run history (no name, no sleep or heart-rate raw data) is sent to Anthropic when the user requests an AI evaluation. The app is a general fitness guide and not a medical device.

**Why not fewer permissions**
Without Sleep, Heart rate, Energy score and Skin temperature the app still works with running data alone; the readiness score is optional. Users can deny those permissions individually.
