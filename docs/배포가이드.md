# RunLog 배포 가이드

이 앱을 다른 사람들이 각자 자기 정보를 입력하고 권한을 허용해서 쓸 수 있게 만들었어요. 이 문서는 **배포 전에 해야 할 일**을 순서대로 정리한 거예요.

## 0. 먼저 결정할 것 (가장 큰 걸림돌)

**삼성 헬스 Data SDK는 공개 배포하려면 삼성의 사전 등록이 필요해요.**

- 삼성 문서: 공개 배포하는 앱이 삼성 헬스 Data SDK를 쓰려면 **삼성 시스템에 사전 등록**이 필요하고, 등록된 서명이 아니면 SDK가 연결을 막아요(AuthorizationException).
- **개발자 모드**는 테스트·디버깅 전용이에요. 삼성은 개발자 모드를 앱 사용자에게 안내하지 말라고 해요.
- 등록은 **파트너십 요청**으로 해요. 앱 **패키지명**과 **서명 SHA-256**을 제출하고, 승인되면 삼성 헬스 시스템에 등록돼요.
- 참고: https://developer.samsung.com/health/data/process.html , https://developer.samsung.com/health/data/guide/app-verification.html

| 배포 범위 | 가능 여부 | 조건 |
|---|---|---|
| 내 폰 | 가능 | 삼성 헬스 개발자 모드(데이터 읽기) 켜기 |
| 가까운 지인 몇 명 (테스트) | 제한적 | APK 직접 설치 + 각자 개발자 모드. 삼성은 사용자에게 개발자 모드를 안내하지 말라고 하므로, 소수 테스터에게만 쓰세요 |
| Google Play 공개 | **삼성 등록 승인 후** | 아래 2~3번 |

**대안(권장 병행)**: Google **Health Connect**를 데이터 소스로 추가하면 삼성 승인 없이도 대부분의 Android 폰에서 쓸 수 있어요. 다만 이 프로젝트에서 이전에 확인한 결과, 삼성 헬스가 Health Connect로 넘기는 러닝 기록은 거리·시간·심박 위주라 **구간별 페이스, 케이던스, 준비운동/마무리 분석이 빠져요**(기능이 줄어든 버전). 코드에 `HealthRepo.kt`(예전 Health Connect 경로)가 남아 있지만 지금 앱에는 연결돼 있지 않아요. 다음 개발 단계에서 '데이터 소스 선택(삼성 SDK / Health Connect)'을 만드는 걸 권해요.

## 1. 이번에 일반화한 것

- 첫 실행 안내(5단계): 개인정보 안내 → 내 정보(닉네임, 출생연도, 성별, 키, 체중, 최대 심박) → 목표(종목, 기록, 주 3/4회, 요즘 주간 거리, 관절 주의) → 데이터 연결 허용(삼성 헬스, 수면·심박·에너지 점수) → 알림·AI 키(선택)
- 설정 탭의 **내 정보 수정**, **내 데이터 모두 지우기**, **앱 정보**(버전, 의료 면책, 개인정보 안내)
- 개발자 개인 값 제거: 키·체중·목표 페이스, 심박 기준(142/145/150 등), 5주 시드 계획, 인사말(이름), 기록 거리 기준(12km, 35km 등)을 모두 **입력값 기준**으로 계산해요.
  - 최대 심박: 입력값 → 없으면 `208 - 0.7 x 나이` → 나이도 없으면 185
  - 이지런 심박 상한 = 최대 심박의 80%, 강한 러닝 = 85%
  - 목표 기록은 Riegel 공식으로 10K 기준 페이스로 환산 (기록을 비우면 최근 기록 기준)
  - 롱런·이지런 거리, 회복 규칙의 거리 기준은 **내 평소 주간 거리**에 비례 (기록이 부족하면 입력한 '요즘 주간 거리')
- 건강 데이터는 앱에 필요한 4종(수면, 심박, 에너지 점수, 피부 온도)만 요청해요.
- 매니페스트 정리: 쓰지 않는 Health Connect 권한과 권한 안내 화면을 뺐고, `allowBackup=false`로 앱 데이터(API 키, 내 정보)가 구글 기기 백업에 올라가지 않게 했어요. (나중에 Health Connect 데이터 소스를 추가하면 필요한 읽기 권한을 다시 넣으세요.)
- 개발용 진단 카드(JSON 복사, 삼성 직접 읽기 테스트, 건강 데이터 진단)는 **디버그 빌드에서만** 보여요.

## 2. 릴리스 빌드 만들기

1. **패키지명을 먼저 확정하세요.** 지금은 `com.jihoon.runlog`예요. 스토어에 올린 뒤에는 바꿀 수 없고, 삼성 등록도 패키지명에 묶여요. 바꾸려면 Android Studio에서 패키지 이름을 리팩터링(Rename)하고 `build.gradle.kts`의 `applicationId`, 매니페스트, `proguard-rules.pro`의 `com.jihoon.runlog.ReminderReceiver`를 같이 바꾸세요.
2. **키스토어 만들기** (한 번만, 분실하면 업데이트 불가):
   ```
   keytool -genkeypair -v -keystore release-keystore.jks -alias runlog -keyalg RSA -keysize 2048 -validity 10000
   ```
3. `keystore.properties.example`을 `keystore.properties`로 복사해서 값을 채우고, `app-build-gradle-release-snippet.txt` 내용을 `app/build.gradle.kts`에 합치세요. `proguard-rules.pro`는 `app/` 폴더에 넣으세요.
4. `.gitignore`에 `keystore.properties`, `*.jks`, `libs/*.aar`를 추가하세요. 삼성 SDK(.aar)는 약관에 동의하고 받은 파일이라 공개 저장소에 올리면 안 돼요.
5. Android Studio → Build → **Generate Signed App Bundle / APK** → Android App Bundle(.aab) 선택 → release.
6. 릴리스 빌드를 폰에 설치해서 확인하세요 (R8 난독화가 삼성 SDK를 깨뜨리는 경우가 있어요). 문제가 생기면 `isMinifyEnabled = false`로 먼저 확인하세요.

> 자세한 순서, 키 만드는 방법, 요청서 초안은 `삼성-파트너등록-준비.md`, 패키지명 변경은 `패키지명변경.md`를 보세요.

## 3. 삼성 파트너 등록 요청

1. https://developer.samsung.com/health 에서 계정을 만들고 파트너십 요청을 제출하세요.
2. 제출 정보: **앱 패키지명**, **서명 SHA-256**, 사용할 데이터 종류.
   - SHA-256: Play Console → 출시 → 설정 → **앱 무결성** → '앱 서명 키 인증서'의 SHA-256 (Play 앱 서명을 쓰는 경우, 배포되는 앱의 서명은 Play의 키예요)
   - 데이터 종류(읽기만): 운동(Exercise), 수면(Sleep), 심박(Heart rate), 에너지 점수(Energy score), 피부 온도(Skin temperature)
3. 승인될 때까지 공개 배포하지 마세요. 승인 전에는 개발자 모드가 켜진 기기에서만 동작해요.

## 4. Google Play 준비 (Play Console에서 현재 요구사항을 꼭 확인하세요)

- 개인정보처리방침: `privacy-policy-ko.md`를 채워서 **공개 웹 주소**에 올리고, 스토어와 앱(`PRIVACY_POLICY_URL`)에 넣기
- 앱 콘텐츠 설문: 데이터 보안(건강·피트니스 정보를 기기 안에서만 처리, 선택 기능으로 AI 서비스에 전송), 대상 연령, 광고 없음, 건강 앱 관련 선언이 있으면 작성
- 권한 설명: 캘린더 읽기·쓰기(훈련 일정 공유), 알림, 정확하지 않은 알람
- 스토어 등록 정보: `store-listing-ko.md`, 아이콘, 스크린샷
- 테스트 트랙: 내부 테스트 → 비공개/공개 테스트 순서로 올리세요. 새 개발자 계정은 공개 출시 전에 일정 기간·인원 이상의 비공개 테스트가 요구될 수 있어요.
- 대상 API 레벨 등 Play 정책은 수시로 바뀌니 출시 직전에 Play Console의 안내를 확인하세요.

## 5. 출시 전 테스트 체크리스트

- [ ] 새로 설치 → 첫 실행 안내 5단계 완주 (키 120~230, 체중 30~250 등 입력 검사 포함)
- [ ] 권한을 모두 거부해도 앱이 죽지 않고 안내가 보임 (삼성 헬스, 건강 데이터, 알림, 캘린더)
- [ ] 러닝 기록이 0건인 새 사용자: 홈이 비어도 정상, 첫 동기화 후 계획 생성
- [ ] 초보자 프로필(주간 5km, 목표 없음)과 숙련자 프로필(주간 50km, 하프 1:40)에서 계획 거리가 자연스러운지
- [ ] 주 3회 / 주 4회 선택에 따라 일요일 선택 훈련이 달라지는지
- [ ] 최대 심박을 비웠을 때와 입력했을 때 심박 기준이 바뀌는지
- [ ] 내 정보 수정 → 새 계획 반영
- [ ] 내 데이터 모두 지우기 → 앱 종료 → 재실행 시 첫 실행 안내가 다시 나옴
- [ ] 릴리스 빌드(난독화)에서 삼성 연동, 동기화, 새 계획, 캘린더 공유, 알림이 모두 동작
- [ ] 다크/라이트, 작은 화면, 큰 글자 설정에서 텍스트가 잘리지 않는지

## 6. 알려진 한계 (공개 배포 관점)

- **삼성 헬스 전용**: 삼성 헬스가 없는 폰, 갤럭시 워치가 없는 사용자는 수면·에너지 점수·구간 기록이 비어요.
- 한국어만 지원해요.
- 훈련 계획 틀은 '주 3~4회, 이지런·템포·인터벌·롱런'이에요. 주 5회 이상, 트레일, 마라톤 전용 주기화는 아직 없어요.
- 거리 기준은 평소 주간 거리에 비례해서 맞추지만, 완전 초보자나 엘리트 러너는 추가 검증이 필요해요.
- 피로도·컨디션 점수의 가중치와 심박 기준(최대 심박 80%/85%)은 일반적인 규칙으로 정한 값이고, 개인별로 검증되지 않았어요.
- 이 앱은 의료기기가 아니에요. 심박 이상, 흉통 같은 증상은 훈련 조정이 아니라 전문가 상담 대상이라고 앱 안에서 안내해요.
- 법률(개인정보 보호법 등) 검토는 포함돼 있지 않아요. 공개하기 전에 전문가 확인을 권해요.
